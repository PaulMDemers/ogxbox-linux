## Artifact Classification

### Active and protected

- `artifacts/devuan-5.8.1-nondisc/`: exact hardware-tested terminal and desktop baseline.
- `artifacts/kernels/xbox-linux-5.8.1-fatx-rd-gzip-*`: kernel and config used by that baseline.
- `artifacts/hdd/xbox-devuan-daedalus-i386.ext2`: terminal root payload source.
- `artifacts/hdd/xbox-devuan-daedalus-i386-desktop-full.squashfs`: desktop payload source.
- `artifacts/initramfs/xbox-distro-hdd-ext2-stage1.cpio`: FATX-to-distro stage one.
- `artifacts/softmod/xromwell-hddfatx-devuan-loader-3fa5e65-sector512.zip`: pinned launcher source archive.

### Historical evidence: retain for now

- `artifacts/rev-2026-06-06/` and `artifacts/rev-2026-06-12/`: complete release sweeps with different generated ISO/XBE bytes.
- `artifacts/softmod/`: loader stability experiments and desktop variants used during hardware diagnosis.
- Root-level `artifacts/*.iso`: optical boot experiments and intermediate milestones.
- `worktrees/cromwell-*`: source states used to generate and compare loader diagnostics.

### Generated scratch: safe to regenerate

- `build/release-rev-*`: staging copies for completed release sweeps.
- `build/layout-probe*` and `build/xdvdfs-layout-probe*`: XDVDFS naming/layout experiments.
- Python `__pycache__` directories and root `%ln*` shell-output accidents.

The 2026-08-02 guarded cleanup removed 4,388.3 MiB from these generated
locations. It did not modify `artifacts/`, any source checkout, or either
hardware-tested Devuan ZIP. A dry run is the cleanup script's default.

## Current Technical Status

- **Devuan 5.8 non-disc:** terminal and desktop boot on xemu and real hardware. This is the stable base for further work.
- **Devuan 5.8 cold boots:** the protected terminal package passed 3/3 fresh xemu boots, reaching Linux text at 45 seconds and the proof shell in 80-86 seconds. The protected desktop passed 3/3, reaching Linux in 45-46 seconds, X in 85-86 seconds, and a populated terminal in 91-97 seconds. One of two earlier exploratory desktop boots stalled while Xromwell loaded the initramfs, so loader reliability remains worth watching despite the clean measured batches. See `docs/devuan-5.8-cold-boot-reliability.md`.
- **Linux 5.8 FATX:** read-only FATX is sufficient to locate and loop-mount distro payload files from E:.
- **Linux 6.18:** Xbox bringup works in several paths, but the release sweep still has unresolved optical/root-mount and desktop behavior. Commit `829b71ab17ed` adds the xemu-validated existing-file-only FATX write path. Commit `502b7bb738cf` is the clean read-only rollback point. Real-hardware write testing remains opt-in and experimental.
- **Tiny Core:** 5.8 hardware boots have succeeded; 6.18 testing produced a mix of mount failures, panics, terminal-only boots, and optical tray detection failures. Neither should supersede the Devuan baseline yet.
- **Cromwell/Xromwell:** the sector512 XBE hash above is the known launcher baseline. Later loader timing/trace branches remain diagnostic only.
- **Optical boot:** useful for experiments, but less reliable than the validated E:-root non-disc path and sensitive to drive/media behavior.
- **xemu launchers:** 44 historical root entry points are classified in `docs/xemu-launchers.md`. Thirty-seven static Linux launchers use the dry-run-tested `scripts/invoke_xemu.ps1`; two Devuan live-disc launchers use the tested temporary-media layer above it. The persistent Xromwell HDD/FATX diagnostic launcher remains explicit by design.

## Reproducible Commands

Build the protected configuration into a new non-disc output set:

```powershell
.\scripts\build_devuan_5_8_nondisc.ps1 -OutRoot artifacts\devuan-5.8.1-nondisc-new
```

Measure repeated cold boots without modifying the protected packages:

```powershell
.\scripts\test_devuan_5_8_cold_boots.ps1 -Variant all -Runs 3
```

Audit cleanup candidates without deleting them:

```powershell
.\scripts\cleanup_generated_workspace.ps1
```

Apply only the guarded generated-file cleanup:

```powershell
.\scripts\cleanup_generated_workspace.ps1 -Apply
```
